# X 媒体下载器：完整图片与 HLS 清单设计

## 目标

解决图片延迟加载导致的漏采；同一推文中发现 1 到任意数量的图片都必须采集。对于没有直接 MP4 的视频，保存其 HLS `.m3u8` 播放清单。每次打开侧边栏均开始新会话，不保留之前的采集列表、日志或扫描状态。

## 新会话规则

侧边栏加载时向后台发送 `RESET_SESSION`。后台停止现有自动滚动、清除活动任务引用，并返回空闲状态。历史下载文件、Chrome 已写入的目录和旧的存储记录不被删除；它们只是不再显示或参与本次采集。

## 完整图片采集

图片数量没有业务上限：对每条推文的媒体数组和其对应 DOM 卡片，发现多少图片就创建多少记录。

1. 网络数据通道递归读取推文媒体数组中的全部 `photo` 条目，不截断数组。
2. DOM 通道从推文 `article` 枚举全部媒体图片作为补充。
3. MutationObserver 收到任意新增节点时，查找该节点最近的 `article` 并重扫整张卡片；不只处理新增 `article`。
4. 每次手动或自动滚动后，延迟一次可见卡片复扫，以捕捉已存在卡片中晚到的图片节点。
5. 以推文 ID、媒体序号与原始 URL 去重，避免复扫造成重复项。

自动化测试覆盖：单推文 2、4、8 张图片，以及先出现一张、随后在同一 `article` 插入更多图片的情况。

## 视频回退

视频解析顺序如下：

1. 存在 `video/mp4` 变体时，下载 bitrate 最大的 MP4。
2. 不存在 MP4、但存在 `application/x-mpegURL` 变体时，将该 URL 作为可下载项目，类型显示为 `HLS 播放清单`，扩展名为 `m3u8`。
3. 两者均不存在时，归类为不可下载，并说明原因。

HLS 清单下载只保存 `.m3u8` 文本，不下载音视频分片，也不承诺离线播放或转码为 MP4。列表必须清楚展示该限制。

## 列表与下载

媒体列表继续按可下载与不可下载分 Tab。可下载 Tab 同时包括图片、MP4 和 HLS 清单；每项显示原始 URL、类型、状态和单项下载按钮。批量下载将 HLS 清单与其他待下载媒体一起保存。文件采用已有的 `用户名/日期_序号.扩展名` 规则。

## 验收标准

- 每次重新打开侧边栏均显示空闲状态和“开始扫描”，不显示旧媒体清单。
- 同一推文内 1 到 N 张图片均进入可下载列表，复扫不造成重复。
- 延迟插入到既有推文卡片的图片也会被采集。
- 有 MP4 的视频下载最高码率 MP4；仅有 HLS 的视频下载 `.m3u8` 文件并标注限制。
- 批量和单项下载均可处理图片、MP4 与 HLS 清单，失败状态与原因可见。
