# X 媒体下载器：下载与滚动方案

## 已确认目标

在正在访问的 X 用户主页中采集该用户发布的图片和视频；扫描从当前已加载内容持续到页面底部。媒体按原图或最高码率 MP4 下载，并写入用户选择的文件夹：

```text
用户名/
  2026-08-16_01.jpg
  2026-08-16_02.jpg
  2026-08-16_03.mp4
```

日期取推文发布日期；同日同一推文的多媒体以序号区分。文件名不显示推文 ID。

## 用户流程与界面状态

扫描和下载是两个明确分开的阶段，不再在停止扫描时自动开始下载。

1. **待开始**：选择“手动滚动”或“自动滚动”，再点击“开始扫描”。
2. **扫描中**：实时展示发现数量、当前卡片数和日志。
   - 手动模式：用户自行滚动页面，扩展只监听新加载内容。
   - 自动模式：扩展按约 0.8 个视口向下滚动；提供“暂停自动滚动 / 继续自动滚动”和“停止扫描”。
3. **扫描完成**：保留采集清单，显示“选择文件夹并开始下载”。
4. **选择文件夹并下载**：用户点击后由侧边栏立即弹出浏览器目录选择器；目录确认后才开始写入文件。
5. **下载中/完成**：显示待下载、下载中、成功、失败、无可用 MP4 的计数和逐项日志；失败项可重试。

自动滚动连续三轮未出现新的卡片或新媒体时自动暂停并提示“可能已到底部”，用户仍可继续或停止扫描，避免将临时加载延迟误判为结束。

## 媒体发现

采用两条互补通道，并以媒体键去重：

- **DOM 通道**：从 X 推文卡片中提取图片、视频元素、封面图、推文链接和日期。图片 URL 统一转换为 `name=orig`。
- **页面网络通道**：在页面主世界拦截 `fetch` 和 `XMLHttpRequest` 的 JSON 响应，递归识别 X GraphQL 推文媒体实体。对 `video_info.variants` 仅接受 `video/mp4`，按 `bitrate` 取最大值；没有可下载 MP4 时，作为“无可用 MP4”记录原因，不伪装成成功。

DOM 发现的视频候选会先入队为“等待解析”；网络通道取得同一媒体的 MP4 变体后补全下载 URL。这样既能立即显示视频被发现，也不会把 poster 当成视频文件下载。

## 下载实现

“选择文件夹并开始下载”必须由用户点击触发。侧边栏调用 File System Access API 的目录选择器，随后：

1. 在所选目录创建用户名子文件夹；
2. 扩展背景页以受 host permissions 保护的请求获取已解析的原图/MP4；
3. 通过目录句柄直接写入对应文件，并按有限并发执行；
4. 每项结果回写任务状态和日志。

目录句柄只用于本次下载会话；浏览器重启或权限失效时，重新点击下载即可再次选择目录。若浏览器不支持目录选择器，界面将明确提示，而不会静默落到浏览器默认下载目录。

## 消息与任务状态

任务保存采集选项、滚动模式、扫描状态、自动滚动状态、媒体列表及日志。核心状态为：

```text
idle -> scanning -> scan_complete -> choosing_folder -> downloading -> complete
                 \-> stopped
```

自动滚动的 `paused` 是 `scanning` 的子状态。侧边栏每秒读取状态，同时内容脚本主动上报扫描、滚动和解析事件，便于在面板日志中排查页面注入或网络解析问题。

## 验收标准

- 手动滚动一页包含图片和视频的用户主页时，计数与日志均会增加。
- 自动模式可暂停、继续、停止，且不会与手动模式同时运行。
- 图片下载为原图；已解析的视频下载为最高码率 MP4。
- 停止扫描不会下载；点击下载后必须先选择一次目标文件夹。
- 文件按用户名目录和“日期_序号.扩展名”命名，不显示推文 ID。
- 无可用 MP4、解析失败、文件写入失败均有可见日志与准确计数，并支持失败重试。
- 为网络实体解析、滚动状态机、文件命名与下载队列补充自动化测试；完整测试套件通过后再交付。
