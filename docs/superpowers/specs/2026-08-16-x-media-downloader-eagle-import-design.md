# X 媒体下载器：Eagle 直接导入设计

## 目标

让用户把已扫描到的可直接访问资源保存到当前打开的 Eagle 资料库，并保留资源所属 X 推文作为来源网址。

## 范围

1. 扩展通过 Eagle 本机 API `http://localhost:41595/api` 检测 Eagle 是否可用。
2. 导入前自动确保 Eagle 根目录存在名为 `@推主用户名` 的文件夹；存在时复用，缺失时创建。
3. 列表中每项和下载区顶部均提供“保存到 Eagle”操作；批量操作只导入当前可导入项目。
4. 图片和直链 MP4 作为 Eagle 文件导入；HLS 播放清单不在此阶段导入，避免 Eagle 将其误判为普通文本资源。
5. Eagle 条目名称沿用扩展生成的下载文件名；来源网址固定为 `https://x.com/i/status/<tweetId>`；标签包含 `X`、任务用户名、`图片`、`视频` 或 `HLS`。
6. Eagle 未打开、文件夹读取失败或单项导入失败时，在面板状态和日志中展示明确错误，其余项目继续导入。

## 非范围

- 不导入用户目录中已下载的本地 MP4。浏览器扩展无法安全取得这些文件的绝对路径；该能力留给后续本地桥接程序。
- 不创建、删除或修改 Eagle 文件夹。
- 不上传任何数据到远端服务。

## 架构

- `src/shared/eagle.js`：纯函数，负责从扫描记录生成 Eagle 条目数据、推文来源链接和标签，便于单测。
- `src/background/service-worker.js`：请求 Eagle 本机 API，查询或创建推主根目录文件夹并逐项导入；通过既有任务状态与日志协议回传结果。
- `src/panel/*`：新增 Eagle 区域、自动目标文件夹提示、批量和单项操作。只显示当前可导入媒体；HLS 不在此阶段导入。
- `manifest.json`：仅增加 `localhost:41595` 主机权限。

## 验收

- Eagle 已打开时自动复用或创建推主根目录文件夹，并成功导入一项或多项媒体。
- Eagle 条目的来源链接为其所属推文，而不是 CDN 文件链接。
- 图片、MP4 与 HLS 的标签和导入方式正确。
- Eagle 未打开时用户得到可操作的提示，扩展下载与扫描功能不受影响。
