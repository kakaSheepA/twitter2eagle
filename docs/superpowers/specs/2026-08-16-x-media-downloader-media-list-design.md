# X 媒体下载器：媒体列表与下载区设计

## 目标

将扫描操作、批量下载和单项下载解耦。用户能在侧边栏查看每个已发现媒体的原始链接、可下载状态和下载进度，并可按可下载与不可下载分类查看。

## 侧边栏布局

1. **扫描区**：包含转推/回复选项、手动/自动滚动选择，以及唯一的“开始扫描”或“停止扫描”主按钮。
2. **下载区**：扫描结束后展示独立的“批量下载”按钮。点击后选择一次目标文件夹，下载所有可下载且仍处于待下载状态的媒体。
3. **媒体列表**：下载区下方提供两个 Tab：`可下载 (N)` 与 `不可下载 (N)`。

扫描按钮绝不直接开始下载；批量下载按钮也不会开始新的扫描。

## 列表项

每个列表项显示：

- 类型（图片 / 视频）与推文发布日期；
- 状态（待下载、下载中、已完成、失败，或不可下载原因）；
- 原始媒体 URL：可点击并在新标签页打开；
- 可下载项的“下载”按钮。

不可下载 Tab 只包含 `status: unavailable` 的项目，并显示具体原因；不显示下载按钮。可下载 Tab 包含有直接 URL 的图片和 MP4 视频，以及下载中的、已完成和失败项。

## 下载规则

- **批量下载**：点击后必须选择一次目录；在该目录的用户名子目录中写入所有待下载可下载项。
- **单项下载**：每次点击都必须选择目录，只写入当前这一项；不复用此前批量下载的目录，避免用户不清楚落盘位置。
- 单项下载与批量下载共享现有写入逻辑、文件命名、日志和状态更新。
- 下载中的项目禁用自身下载按钮；已完成项目显示完成状态，失败项目可以再次点击下载。

## 数据和消息

后台新增按任务项目下载的入口：面板在选择目录后发送待下载的单个项目键或批量项目键；每项的 `downloading`、`completed`、`failed` 状态仍由 `DOWNLOAD_ITEM_STATUS` 持久化。列表刷新使用任务当前 `items`，不复制媒体数据。

## 验收标准

- 打开面板时有明确的扫描控制和独立的批量下载按钮，不再有“停止扫描即下载”。
- 可下载与不可下载媒体分别出现在正确的 Tab，计数与任务汇总一致。
- 每条 URL 可点击打开，单项下载会要求选择目录。
- 批量下载只下载可下载 Tab 中待下载的媒体，且只要求选择一次目录。
- 每项下载成功、失败和重试后的状态立即反映到列表、统计和日志。
