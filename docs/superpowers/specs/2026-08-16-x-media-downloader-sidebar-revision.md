# X 媒体下载器侧边栏与 DOM 采集修订设计

## 背景

Chrome action popup 在点击页面、拖动滚动条或切换焦点时按浏览器规则自动关闭，不能显示滚动过程中的采集进度。原有方案将采集完全依赖于 X 内部网络响应结构；实测没有接收到可解析的媒体记录，采集数保持为零。

## 目标

将任务控制界面迁移到 Chrome Side Panel，并以页面 DOM 中实际出现的推文卡片与媒体元素为图片采集的主来源。网络响应解析只作为视频最高码率 MP4 地址的补充来源。

## 用户流程

1. 用户打开 X 用户主页，点击扩展图标打开右侧常驻面板。
2. 面板校验当前页，显示用户名、回复/转推开关和“开始采集”。
3. 开始采集后，用户手动滚动页面。面板保持打开，并实时显示新发现推文、图片、视频及异常数量。
4. 内容脚本用 `MutationObserver` 扫描新增的 `article` 推文卡片：从状态链接获得推文 ID、从 `time` 获得日期、从 `img[src]` 获得图片并切换到原图 URL。
5. 对 `video` 元素，记录推文关联、封面和可用 URL；若页面桥接捕获同一推文的 MP4 variants，则以最高码率地址补全该视频。没有 MP4 的视频保留为不可用状态。
6. 用户滚至最早内容，面板点击“停止采集并下载”。下载、失败重试与本地恢复沿用现有任务队列。

## 操作状态机

面板只显示一个主操作按钮，避免相互矛盾的操作并列出现：

- `idle`：显示“开始采集”。
- `collecting`：显示“停止采集并下载”；点击后锁定采集清单并开始下载。
- `downloading`：主按钮禁用，文字显示当前下载进度。
- `completed`：显示“开始新任务”。

“重试失败项”只有失败数大于零时才显示；没有独立的“开始下载”按钮。

## 架构变更

- `side_panel.default_path` 指向新的 `src/panel/panel.html`，扩展图标点击时打开侧边栏。
- Popup 不再是主操作入口；可保留为“打开侧边栏”快捷入口或移除。
- 内容脚本新增独立 DOM 采集器。它会扫描初始文档并观察新增节点，每条推文以推文 ID 去重。
- DOM 采集与原始网络桥接通过相同的 `MEDIA_DISCOVERED` 消息写入现有任务存储。
- 面板每次打开、操作结束和定时轮询状态，显示发现数量与一条最新诊断信息；采集无变化时能区分“尚未发现媒体”和“内容脚本未连接”。

## 验收标准

1. 点击页面和滚动页面时任务面板不关闭。
2. 含图片的可见推文首次出现后，面板计数会增加，即使 X 网络响应结构变化。
3. 重复渲染同一推文、反复上下滚动不会重复记录媒体。
4. 图片仍下载 `name=orig` 原图；已有 MP4 variant 时视频使用最高码率。
5. 面板能显示“已扫描推文”和“已发现媒体”，便于定位页面没有媒体与采集失败的差别。
6. 任何时刻只显示符合当前任务状态的一个主操作按钮。
